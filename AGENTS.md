# Working on Notebook

A bounded, local prototype of a Goodnotes-like course notebook with peer knowledge. Read `docs/superpowers/specs/2026-11-02-notebook-v2-design.md` and `docs/superpowers/specs/2026-11-05-sharing-live-and-group-notes.md` (current; the 11-01 spec/plan are superseded) `docs/HANDOFF.md` and `docs/PROGRESS.md` before changing behavior. User decisions outrank earlier proposals. ClassFlowAI is reference-only; this repo imports none of its runtime.

- Node >=24, npm with the checked-in lockfile, poppler-utils. `npm ci`, `npm run seed -- <zip|folder>`, `npm run dev`.
- Run `npm run check` and `npm run test:e2e` before reporting changes as working. E2E uses `e2e/mock-llm.mjs`; never point tests at the live provider.
- Live provider configuration (official DeepSeek, `deepseek-flash`, multimodal) belongs in ignored `.env`; uploads and the database belong in ignored `data/`. Never commit credentials or runtime data.
- Students can take several courses; every course-scoped read/write must check enrollment (`x-course-id` header + lecture/fragment course). Never leak lectures, notes or links across courses.
- Demo identities (Thomas, Alex, Priya, and the seeded **Professor**) are explicitly not authentication. Keep the server on loopback.
- No RAG/embeddings by user decision: prompts carry the whole lecture (slide digests + visible classmate fragments). Model citations must be validated server-side against the refs actually supplied.
- Student ink and text are never modified by AI. Suggestions are added only on explicit "Add beside my notes", as separate `annotation` items that are excluded from page rendering for indexing, so generated text is never republished as peer evidence.
- Index results are written only if the page revision is unchanged; annotation-only edits must not trigger a new model call (content hash).
- **AI sharing** is automatic and **not** user-reversible in the demo (user decision, Nov 4): there is no Stop sharing for the anonymous bank. The AI's own reasons (`unclear`, `unlinked`, `on_slide`) are the only thing that keeps an item private; `withheld` stays dormant so author control can return later. Notes that merely restate the slide are not shared. Direct sharing below is a separate, named surface and is also not revocable.
- **Named sharing** (user decisions, Nov 5): three modes. **Send a copy** gives one classmate an editable copy in their **Shared with me** folder, pullable (they can fetch later changes) or snapshot; the sender chooses. **Go live** is the professor's handout: students follow the current page read-only during the session; ending it creates a pullable or snapshot copy for every student. **Invite to co-edit** turns a note into one group note owned by the creator plus editors: invite/accept, object-level merge where a local edit wins, per-user undo, presence. A received copy can be turned into a group note. There is no separate Forward action — sharing the copy again is a new share. No cross-course shares. The professor's copy and the students' copies are raw and named; they are not AI-filtered.
- **The AI bank stays separate and anonymous.** Direct shares, group notes and professor notebooks are never ingested into `knowledge_entries`. A received copy contributes only its recipient's own `origin='own'` additions on slide-anchored pages; the shared layer is never indexed, re-attributed or re-published. The professor's own notes are authority, not peer evidence. AI suggestions never name a classmate; direct shares do name the sender.
- **Roles** (user decisions, Nov 5): only a professor account can create a course; only an instructor can add official slide decks, change the course, re-digest slides or go live. The seeded **Professor** is the instructor of COMP2211. Instructors are excluded from classmate counts, peer-note counts and the AI bank.
- Library layout (user decision, Nov 4): **one free file tree per course**. A course is joined, not created as a folder. Two ordinary folders are seeded once per student per course — **Lectures** (holding the official decks) and **Quizzes** — and are renameable, deletable and movable like any folder; deleting a folder moves its contents up. **My notes** and **All files** are smart views above the tree, not folders. Everything a student owns lives in this tree, including the lecture decks: they keep their `L#`/`PDF` badge and ✎ count wherever they are filed. Notes never move across courses. A **Shared with me** folder is created on the first received copy and is ordinary thereafter (rename, move, delete; if deleted, later copies go to the top level). Group notes live in **My notes** with a Group badge. No add buttons for notebooks/PDFs: PDFs are dropped in, notebooks come from the header button or the long-press/right-click menu; "New folder" and "New notebook" are the two buttons. Tablet is the primary device: every action must work by touch (long-press menu, long-press drag, Move to…).
- Paper (user decision, Nov 4): a notebook is **made from paper**, chosen once at creation — **Lined** (handwriting), **Grid** (equations, diagrams), **Plain** (typing, pasting). `notebooks.paper` is the default for every new page; a single sheet can be re-papered from its page menu without losing what is written on it, and one page can differ from the notebook. Typed text is written *on* the paper: it starts inside the writing column and on a rule, is as wide as the column, and grows downward. The draft is saved while it is being typed, so leaving the notebook never saves an empty box.
- **Ask is a first-class entry point** (Nov 4; panel split Nov 5): the editor header's `✦ Ask` button opens a panel with two tabs. **Ask** is a conversation, not a one-shot card list: a thread of questions and answers, a History menu of sessions for this notebook, a New chat action, and a composer at the bottom. Sessions are per student and notebook; every message records the page it was asked on, so one conversation can span pages. A lasso ask is a one-off about a selection and is not added to history. **Suggestions** is its own tab: This page (the page's suggestions and the author's own notes) or Whole notebook (every suggestion in the notebook grouped by the page it sits on, in notebook order, each row saying what is suggested and where it comes from, expandable to the suggestion itself plus a crop of the classmate's actual handwriting when it comes from one note). `Add to that page` merges it on the page it belongs to **without moving the page being read**; `Go to page` is the separate jump. Both scopes share the page's dismissals, so nothing is offered twice. A page that is not linked to a lecture says so instead of failing.
- **Memo is an object on the note, not a kind of note** (user decision, Nov 4): a small sticky sheet the student sticks anywhere on a page — a reminder, a question to ask, something from elsewhere. It has its own tool (`M`), four paper tints, drag to move, drag its grip to widen, and it types in place. Because it is the student's own writing it is indexed and shareable like ink and text (unlike an `annotation`, which is AI text and stays out of both). Memos are drawn into the page render the model reads.
- Suggestions stay quiet and arrive **inline, like an editor completion** (user decision, Nov 4 — modelled on Copilot in an editor): the suggestion is written faintly into the page in the writing column at the gap, with a `＋` in the margin beside it. One click (or Enter, once focused) accepts it and the text becomes a quoted note below the student's own writing; the page is what remembers the decision, so undoing the note brings the suggestion back. `⋯` in the margin offers Full note (the side card with sources), Not now (away for this visit) and Don't suggest this again (remembered). The ghost takes no pointer events over the writing area, so ink, lasso and eraser still reach the page underneath. The slim panel is closed by default and lists this page's suggestions for overview.
- Peer knowledge reaches a student through the **course knowledge base**, never as raw fragments: the merge job groups notes into `knowledge_entries` with an AI summary, single-source entries keep the note verbatim, and disputed entries are excluded from suggestions and prompts. Sources are never listed and no classmate is ever named; cards carry a neutral line ("From 3 classmates' notes", "From slide 12", "AI explanation"). The one exception, by user decision, is the handwriting crop: a suggestion that comes from exactly **one** classmate's note can show a crop of that note, with no name and no author — it is evidence for judging the suggestion, not a source list. The shared layer of a direct share and a group note is never peer knowledge; a received copy can contribute only its recipient's own slide-anchored additions, and the group note itself stays out.
- The merge and check job runs when the student **leaves** the notebook (`POST /api/notebooks/:id/close`, plus a 10-minute sweep for tabs that never closed). A slide whose notes did not change costs no model call.
- A note replaced by a re-read is **superseded, not deleted**: its row stays so a citation already in someone's notes still resolves.
- Fragments are shared only when the transcription and the slide link are both confident (`SHARE_THRESHOLD`); others stay private and visible to the author. For a received copy, `origin='shared'` objects are excluded from the render the indexer reads; only the recipient's own `origin='own'` additions on slide-anchored pages enter the bank. Group notes and professor notebooks are not indexed at all.
- Quiz answers must be supported by an official slide; questions without a valid slide citation are dropped. There are no reliability labels anywhere: no "unverified", no "Official slides / AI interpretation" basis chips.
- Missing AI configuration must produce a clear error, never fabricated content.
- Mock-provider tests establish transport and control flow only; model quality needs representative inputs and human evaluation.
- `npm run dev` watches both halves: Vite (polling, left on because native watch handles ran out on this workstation once) and the API via `tsx watch`. Use `npm run dev:local` (4312/5174) when the public service is running, since it already holds 4310.
- The public demo `notebook.zh-thomas.party` runs as `notebook.service` from this same working copy via `npm run serve`, which watches and rebuilds. **Every change here is live on the public page within seconds** — no deploy or restart. Keep the tree presentable, and restart the service only after editing `.env`.
